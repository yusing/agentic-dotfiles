# Starter, scaffold, or project template README guide

## Reader and promise

Write for a developer choosing a starting point and turning it into their own
working project. State what is included, the intended ecosystem, and which choices
are opinionated. Distinguish a runnable starter from a catalog of examples or a
personal configuration repository.

## Possible reader path

1. Intended project outcome and opinionated choices
2. Demo or preview, supported environment, and maintenance status
3. Included capabilities and important stack choices
4. Generate or copy the project, install dependencies, and run it
5. Expected local URL or other first-run result
6. Customization checklist for names, metadata, sample data, and configuration
7. Build, test, and deployment paths that the starter supports
8. Variations, deeper guides, and contribution information

## Evidence to gather

For affected claims, inspect template generation, package scripts, example
configuration, deployment files, and repository-specific metadata. Identify what
the user must replace, which files are examples, and how the starter is maintained.

## Fit checks

Make the handoff from upstream template to the user's project explicit. Explain
whether users are expected to track updates or own their copied code. Link stack
documentation rather than teaching every dependency. Keep placeholders and sample
credentials identifiable so they are not mistaken for production settings.

## Observed example

[Vitesse](https://github.com/antfu-collective/vitesse#readme) puts a live demo near
the opening, provides template-copy commands and a customization checklist, then
covers development, build, and deployment. It also states its
maintenance limits. Borrow the preview-to-adoption-to-customization path, not its
particular stack or the assumption that a starter is the best current choice.
